# GAME OVER? 홈페이지 관리자 매뉴얼

해마다 열리는 컨퍼런스를 담는 홈페이지입니다. 이 문서 하나로 운영할 수 있습니다.

- **공개 주소** — https://game-dev-conference-gameover.github.io/GAMEOVER_Homepage/
- **저장소** — `Game-Dev-Conference-GAMEOVER/GAMEOVER_Homepage`

---

## 1. 홈페이지 구조 (연례)

페이지는 두 종류입니다.

| 주소 | 무엇 | 예시 |
| --- | --- | --- |
| **전면** `/` | 컨퍼런스 자체 **범용 소개** (특정 회차 아님) | 이름·슬로건·성격·지난 회차 목록 |
| **회차 아카이브** `/YYYY/` | 그해 행사의 **전체 기록** | `/2026/` — 타임테이블·발표자료·오시는 길·FAQ |

전면은 해가 바뀌어도 거의 그대로 둡니다. 각 행사가 끝나면 그해 기록을 `/2026/`, `/2027/` … 로 쌓아 갑니다.

```
내 컴퓨터는 서버가 아닙니다. 노트북을 꺼도 홈페이지는 계속 떠 있습니다.
배포는 저장소 main 브랜치가 갱신될 때 GitHub 가 자동으로 새로 만듭니다(1~2분).
```

## 2. 무엇을 어디서 고치나 — 가장 중요한 표

내용은 **두 곳**에서 관리됩니다. 어느 쪽인지부터 확인하세요.

| 바꾸려는 것 | 어디서 | 코드 필요? |
| --- | --- | --- |
| 행사 이름·슬로건·한 줄 소개 | **구글 시트** (기본정보 탭) | ✗ |
| 소개 문구("무엇을 하는 자리인가"·"이런 발표는 안 합니다") | **구글 시트** (소개 탭) | ✗ |
| 발표 구조(상황 → 다시 한다면) | **구글 시트** (강연구성 탭) | ✗ |
| 트랙(기업/인디) | **구글 시트** (트랙 탭) | ✗ |
| 주최·연락처 이메일 | **구글 시트** (기본정보 탭) | ✗ |
| **올해 타임테이블·연사·세션** | **코드** (`src/data/editions/2026.ts`) | ✓ |
| **올해 장소·오시는 길** | **코드** (`editions/2026.ts` 의 `venue`) | ✓ |
| **올해 FAQ** | **코드** (`editions/2026.ts` 의 `faq`) | ✓ |
| **발표자료(PDF)** | **코드** (`public/slides/` + `editions/2026.ts` 의 `slides`) | ✓ |
| **내년 회차 추가** | **코드** (`editions/2027.ts` + 라우트) | ✓ |
| 동아리 로고·홈페이지 링크 | **코드** (`src/components/PartnersSection.tsx`) | ✓ |

> ⚠️ **지난 회차는 '동결'됩니다.** `/2026/` 의 타임테이블·장소·FAQ·발표자료는 코드(`editions/2026.ts`)에 박혀 있어, **구글 시트의 일정·오시는길·FAQ 탭을 고쳐도 `/2026/` 는 바뀌지 않습니다.** 끝난 행사의 기록이 시트 실수로 틀어지지 않게 하려는 설계입니다. 시트로 바뀌는 건 **전면 소개에 쓰는 상시 정보(이름·슬로건·소개·발표 구조·트랙)** 뿐입니다.

정리하면:

- **A. 상시 정보 (시트, 코드 불필요)** → 3번
- **B. 회차 관리 (코드)** → 4번

## 3. A. 상시 정보 — 구글 시트로 수정

전면 페이지의 **이름·슬로건·소개·발표 구조·트랙·연락처**가 시트에서 옵니다.

```
구글 시트 수정  →  [사이트 업데이트] 실행  →  1~2분 뒤 반영
```

### 3-1. 갱신하기

시트를 고친 뒤 셋 중 하나:

| 방법 | 하는 법 | 반영 |
| --- | --- | --- |
| **시트 메뉴** (가장 편함) | 시트 상단 **GAME OVER? → 사이트 업데이트** | 1~2분 |
| **GitHub 버튼** | 저장소 → **Actions** → `Deploy to GitHub Pages` → **Run workflow** | 1~2분 |
| **자동** | 아무것도 안 함 | 매일 오전 9시·오후 9시 |

성공 여부는 **Actions** 탭에서 초록 체크(✓)/빨간 엑스(✗)로 확인합니다. 실패해도 기존 홈페이지는 그대로 살아 있고, 이유가 한글로 나옵니다.

### 3-2. 시트 탭

탭 이름은 바꾸지 마세요(철자 그대로 읽습니다).

| 탭 | 전면에 반영됨? | 메모 |
| --- | --- | --- |
| **기본정보** | ✅ 이름·슬로건·한 줄 소개·주최·이메일 | 날짜·장소·신청주소 칸은 지금은 전면에 쓰이지 않음(회차=코드) |
| **소개** | ✅ 소개 문구·제외 목록 | |
| **강연구성** | ✅ 상황 → 다시 한다면 | |
| **트랙** | ✅ 기업/인디 | |
| **일정** | ❌ (지난 회차는 코드로 동결) | 시트 검증은 계속 돌지만 라이브엔 영향 없음 |
| **오시는길** | ❌ | 〃 |
| **FAQ** | ❌ | 〃 |

> 시트의 일정·오시는길·FAQ 탭은 **빌드 검증은 여전히 거칩니다**(형식이 깨지면 배포가 멈춤). 라이브에 반영되지 않을 뿐이니, 형식은 유지해 주세요.

## 4. B. 회차 관리 — 코드

날짜·타임테이블·장소·FAQ·발표자료와 내년 회차는 코드로 관리합니다. **GitHub 웹에서 직접 편집**하거나(간단한 경우), 로컬에서 고친 뒤 push 합니다. `main` 에 반영되면 1~2분 뒤 배포됩니다.

> 데이터 경계 요약
> - `src/data/conference.ts` — 상시 정보(시트 구독). 손대지 않아도 됩니다.
> - `src/data/editions/2026.ts` — **2026 회차의 모든 것(동결)**: 날짜·장소·타임테이블·FAQ·발표자료.
> - `src/data/editions/index.ts` — 회차 목록.
> - `src/data/schedule.ts` — 회차 공통 타입·헬퍼.

### 4-1. 발표자료(PDF) 올리기·교체

1. PDF 를 `public/slides/` 에 올립니다. 파일 이름은 **세션 slug** 로 맞춥니다.
   - 현재: `industry-2.pdf`(강현우) · `indie-1.pdf`(이규빈) · `indie-2.pdf`(이문빈) · `indie-3.pdf`(이재우) · `indie-4.pdf`(이느하=매직대학생).
2. `editions/2026.ts` 의 `slides` 에 `"세션slug": "/slides/파일.pdf"` 로 등록합니다.
3. 등록된 세션 카드에만 **"발표 자료 PDF ↗"** 버튼이 생깁니다. 공개를 원치 않는 연사는 넣지 않습니다(예: 하상석 `industry-1` 제외).

### 4-2. 올해 타임테이블·장소·FAQ 고치기

`editions/2026.ts` 에서 해당 항목을 고칩니다.

- 타임테이블: `schedule` 배열의 줄(시작/종료/구분/제목/연사/소속/주소이름/요약).
  - `구분`(kind)은 `공통`·`휴식` 또는 트랙 이름(`기업`/`인디`).
  - 시작 시각이 같은 줄은 화면에서 한 행에 나란히 놓입니다.
- 장소: `venue`(name/address/transit/mapUrl/note).
- FAQ: `faq` 배열(q/a).

### 4-3. 내년 회차 추가 (핵심)

세 가지면 끝납니다.

1. **`src/data/editions/2027.ts` 생성** — `2026.ts` 를 복제해 값만 2027 로. (`year`, `no`="제2회", `dateLabel`, `venue`, `schedule`, `faq`, `slides` 등)
2. **`src/data/editions/index.ts` 에 등록** — 배열 맨 앞에 추가:
   ```ts
   import { edition2027 } from "./2027";
   export const editions = [edition2027, edition2026];
   ```
   (최신이 앞. `latestEdition` 과 전면 "지난 회차" 카드 순서가 이 배열을 따릅니다.)
3. **`src/app/2027/page.tsx` 생성** — `src/app/2026/page.tsx` 를 복제하고 `edition2026` → `edition2027`, 제목의 연도만 바꿉니다.

sitemap·전면 "지난 회차" 목록은 자동으로 따라옵니다. 라우트가 준비 중이면 `status: "upcoming"` 으로 두고 전면에서 "준비 중" 카드로 안내할 수도 있습니다.

### 4-4. 동아리 로고·홈페이지 링크

`src/components/PartnersSection.tsx` 의 `CLUBS` / `SPONSORS` 목록에서 관리합니다.

- 로고 파일: `public/images/logos/` 에 흰색·투명 배경 PNG(3:1 캔버스).
- 홈페이지 버튼: 항목에 `url` 을 넣으면 로고 아래 **"홈페이지 ↗"** 버튼이 생깁니다. `url` 이 없으면 버튼 없음.
  ```ts
  { name: "동명대 UPTRAND", file: "/images/logos/club-uptrand.png", url: "https://uptrand-admin.github.io/Homepage/" },
  ```

### 4-5. 코드 편집·배포 방법

- **GitHub 웹**: 저장소에서 파일을 열고 연필(✏️) 아이콘 → 수정 → **Commit changes**(main 에 바로, 또는 브랜치+PR). main 반영 시 자동 배포.
- **로컬**: `npm install` → `npm run dev` 로 `localhost:3000` 확인 → `git commit` → `git push`.
  - 큰 변경은 브랜치에서 작업하고 PR 로 합치는 것을 권합니다(예: 연례 구조 전환 때 `annual-restructure` 브랜치 사용).

## 5. 배포 확인 / 문제 해결

| 증상 | 원인과 해결 |
| --- | --- |
| 바꿨는데 라이브에 없음 | 캐시입니다. 새로고침(Ctrl/Cmd+Shift+R). Actions 초록불 확인 |
| 시트 고쳤는데 타임테이블 그대로 | **정상.** 지난 회차 타임테이블은 코드(editions)로 동결됨 → 4-2 |
| `시트를 읽을 권한이 없습니다` | 시트 공유가 비공개로 바뀜 → 6-2의 공유 설정 |
| `탭을 찾을 수 없습니다` | 탭 이름이 바뀜 → `sheet-template` 의 CSV 이름과 똑같이 |
| 빌드 실패(빨간 ✗) | Actions 에서 항목 클릭 → `Build static site` 로그에 한글 이유 |
| 저장소 이름 바꾼 뒤 화면 깨짐 | basePath(`/저장소이름/...`)가 빌드 때 구워짐 → Actions 재실행 필수 |
| 발표자료 버튼 안 보임 | `public/slides/` 에 파일 있는지 + `editions` 의 `slides` 에 등록됐는지 |
| 로컬 `next build` 가 `out` 잠김(EBUSY) | dev 서버 실행 중 → preview/dev 중지 후 빌드 |
| 리팩터 후 dev 가 옛 화면 | `.next` 폴더 삭제 후 `npm run dev` 재시작 |

로컬에서 시트 점검: `SHEET_ID="시트주소" npm run sheet:check`

## 6. 처음 한 번만 하는 설정

### 6-1. GitHub Pages 켜기
저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로.

### 6-2. 시트 연결 (상시 정보용)
1. `sheet-template` 폴더의 CSV 를 내려받아, **파일 이름과 똑같은 이름의 탭**으로 구글 시트에 가져옵니다(가져오기 → 현재 시트에 삽입, 구분 문자 쉼표).
2. 시트 **공유 → "링크가 있는 모든 사용자 · 뷰어"**.
3. 시트 주소의 ID 복사: `.../spreadsheets/d/`**`이 부분`**`/edit`.
4. 저장소 **Settings → Secrets and variables → Actions → Variables → New variable**: Name `SHEET_ID`, Value 에 ID.

### 6-3. 시트 업데이트 버튼(Apps Script, 선택)
시트 **확장 프로그램 → Apps Script** 에 아래를 붙여 저장하면 상단에 `GAME OVER?` 메뉴가 생깁니다.
**토큰은 코드에 적지 말고** 프로젝트 설정 → 스크립트 속성에 `GITHUB_TOKEN`(GitHub Fine-grained PAT, 권한 `Contents: Read and write` + `Actions: Read`)으로 넣습니다.

```javascript
const OWNER = 'Game-Dev-Conference-GAMEOVER';
const REPO  = 'GAMEOVER_Homepage';
const TABS = ['기본정보', '소개', '강연구성', '트랙', '일정', '오시는길', 'FAQ'];

function onOpen() {
  SpreadsheetApp.getUi().createMenu('GAME OVER?')
    .addItem('사이트 업데이트', 'updateSite')
    .addItem('배포 상태 확인', 'checkDeploy')
    .addToUi();
}
function token_() {
  const t = PropertiesService.getScriptProperties().getProperty('GITHUB_TOKEN');
  if (!t) throw new Error('스크립트 속성에 GITHUB_TOKEN 이 없습니다.');
  return t.trim();
}
function api_(path, options) {
  const opts = options || {};
  opts.headers = { Authorization: 'Bearer ' + token_(), Accept: 'application/vnd.github+json' };
  opts.muteHttpExceptions = true;
  return UrlFetchApp.fetch('https://api.github.com/repos/' + OWNER + '/' + REPO + path, opts);
}
function updateSite() {
  const ui = SpreadsheetApp.getUi();
  const res = api_('/dispatches', {
    method: 'post', contentType: 'application/json',
    payload: JSON.stringify({ event_type: 'update-content' }),
  });
  const code = res.getResponseCode();
  if (code === 204) { ui.alert('업데이트를 시작했습니다. 1~2분 뒤 「배포 상태 확인」을 눌러 보세요.'); return; }
  const hint = { 401:'토큰 확인', 403:'토큰 권한(Contents: Read and write) 확인', 404:'OWNER/REPO 철자 확인' }[code] || '알 수 없는 오류';
  ui.alert('실패 (' + code + ')\n' + hint + '\n' + res.getContentText());
}
function checkDeploy() {
  const ui = SpreadsheetApp.getUi();
  const res = api_('/actions/runs?per_page=1');
  if (res.getResponseCode() !== 200) { ui.alert('상태를 읽지 못했습니다 (' + res.getResponseCode() + ').'); return; }
  const run = JSON.parse(res.getContentText()).workflow_runs[0];
  if (!run) { ui.alert('실행 기록이 없습니다.'); return; }
  let msg = run.status !== 'completed' ? '빌드 중입니다. 조금 뒤 다시 눌러 보세요.'
          : run.conclusion === 'success' ? '성공했습니다. 홈페이지에 반영됐습니다.'
          : '실패했습니다. 아래 주소에서 이유를 확인하세요.';
  ui.alert(msg + '\n\n' + run.html_url);
}
```

> 토큰은 만료됩니다. 만료일을 인수인계 문서에 남기세요. 만료돼도 Actions 수동 실행은 계속 됩니다.
