# GAME OVER? 홈페이지 통합 관리 매뉴얼

후임 운영자를 위한 문서입니다. **대부분의 작업은 AI 에이전트(Claude Code 등 MCP)에게 시켜서** 처리하는 것을 전제로, 상황별 대응법과 그 바탕이 되는 구조·설정을 한 곳에 담았습니다.

- **공개 주소** — https://game-dev-conference-gameover.github.io/GAMEOVER_Homepage/
- **저장소** — `Game-Dev-Conference-GAMEOVER/GAMEOVER_Homepage`

> 읽는 법: **3번(상황별 대응)** 이 핵심입니다. 각 상황마다 `[에이전트에게]` 복붙용 요청 예시가 있습니다. 왜 그렇게 되는지·직접 하는 법은 **4~6번(레퍼런스)** 에 있습니다.

## 1. 먼저 알아둘 것 — 구조와 데이터 경계

### 1-1. 페이지는 두 종류 (연례 구조)

| 주소 | 무엇 |
| --- | --- |
| **전면 `/`** | 컨퍼런스 자체 범용 소개(이름·슬로건·성격·지난 회차 목록) |
| **회차 아카이브 `/YYYY/`** | 그해 행사의 전체 기록(타임테이블·발표자료·오시는 길·FAQ). 예: `/2026/` |

### 1-2. 내용은 두 곳에서 관리 — **가장 중요**

| 바꾸려는 것 | 어디서 | 코드 |
| --- | --- | --- |
| 이름·슬로건·한 줄 소개·주최·이메일 | 구글 시트 (기본정보 탭) | ✗ |
| 소개 문구·"이런 발표는 안 합니다" | 구글 시트 (소개 탭) | ✗ |
| 발표 구조(상황 → 다시 한다면) | 구글 시트 (강연구성 탭) | ✗ |
| 트랙(기업/인디) | 구글 시트 (트랙 탭) | ✗ |
| **올해 타임테이블·연사·세션** | 코드 `src/data/editions/2026.ts` | ✓ |
| **올해 장소·오시는 길** | 코드 `editions/2026.ts` 의 `venue` | ✓ |
| **올해 FAQ** | 코드 `editions/2026.ts` 의 `faq` | ✓ |
| **발표자료(PDF)** | 코드 `public/slides/` + `editions/2026.ts` 의 `slides` | ✓ |
| **내년 회차 추가** | 코드 `editions/2027.ts` + 라우트 | ✓ |
| 동아리 로고·홈페이지 링크 | 코드 `src/components/PartnersSection.tsx` | ✓ |

> ⚠️ **지난 회차는 '동결'됩니다.** `/2026/` 의 타임테이블·장소·FAQ·발표자료는 코드에 박혀 있어, **구글 시트의 일정·오시는길·FAQ 탭을 고쳐도 `/2026/` 는 바뀌지 않습니다.** 끝난 행사 기록이 시트 실수로 틀어지지 않게 하려는 설계입니다. 시트로 바뀌는 건 전면 소개의 상시 정보뿐입니다.

### 1-3. 배포

```
구글 시트 수정 → [사이트 업데이트] → 1~2분 뒤 반영   (상시 정보)
코드 수정 → main 에 반영(push/머지) → 1~2분 뒤 반영   (회차)
```

내 컴퓨터는 서버가 아닙니다. 노트북을 꺼도 사이트는 떠 있습니다.

## 2. AI 에이전트와 일하는 법

후임자는 대개 **에이전트에게 요청 → 에이전트가 코드·시트를 다룸** 으로 일합니다. 아래 5원칙을 지키면 사고가 나지 않습니다.

1. **로컬에서 먼저 검증시키기.** "`npm run dev` 로 띄워서 화면/SSR 로 확인한 뒤 알려줘." 눈으로 확인 전엔 반영하지 않습니다.
2. **큰 변경은 브랜치 + PR.** "바로 main 에 올리지 말고 브랜치로 올려줘. 머지는 내가 확인하고." 전면 구조 변경, 회차 추가 등이 해당.
3. **푸시·머지는 사람이 확정.** 에이전트가 올려도 되는지 마지막엔 내가 승인합니다.
4. **공개 범위를 명시.** 발표자료는 **공개 동의한 연사만**(비공개 연사 slug 제외). 개인정보(연락처·이메일)는 코드·사이트에 넣지 않습니다.
5. **끝나면 보고받기.** "무엇을 바꿨고 어떻게 확인했는지" 요약을 받습니다.

### 2-1. 세션 시작 시 에이전트에게 붙여넣을 컨텍스트

새 에이전트 세션을 시작할 때 이 블록을 그대로 붙여넣으면 빠르게 파악합니다.

```
이 저장소는 GAME OVER? 컨퍼런스 홈페이지야(Game-Dev-Conference-GAMEOVER/GAMEOVER_Homepage).
Next.js 정적 export → GitHub Pages(basePath /GAMEOVER_Homepage), main push 시 자동 배포.
구조: 전면 '/'(범용 소개) + 회차 아카이브 '/2026/'.
데이터 경계가 핵심 —
 - src/data/conference.ts: 이름·슬로건·소개·발표구조·트랙(구글 시트=content.json 구독).
 - src/data/editions/<year>.ts: 그해 날짜·장소·타임테이블·FAQ·발표자료(코드에 동결, 시트 영향 없음).
 - src/data/schedule.ts: 회차 공통 타입/헬퍼.
회차 섹션(Hero·Program·Venue·Faq·JsonLd)은 edition prop, 상시 섹션(Header·About·Partners·Landing*)은 conference 사용.
작업 규칙: 로컬(npm run dev, localhost:3000)로 검증하고, 큰 변경은 브랜치로, push/머지는 내 확인 받고 해.
자세한 운영 매뉴얼은 docs/관리자-매뉴얼.md 참고.
```

> 팁: 에이전트가 콘솔에서 `content is not defined` 류 에러를 보고하면 대개 `.next` 캐시(리팩터 전) 잔류입니다. 진짜 확인은 `curl localhost:3000` SSR HTML 로 하라고 알려주세요.

## 3. 상황별 대응 플레이북

각 항목: **[상황]** → **[에이전트에게]**(복붙 예시) → **[확인]** → **[주의]**.

### 3-1. 콘텐츠 수정

**① 이름·슬로건·소개 문구를 바꾸고 싶다**
- [상황] 전면 소개 문구/슬로건/발표 구조 수정. (상시 정보 = 시트)
- [대응] 코드가 아니라 **구글 시트**에서 고치고 [사이트 업데이트]. (2번 레퍼런스 참고) 에이전트가 필요하면: `[에이전트에게]` "기본정보/소개 탭에서 바꿀 값만 알려줘, 내가 시트에 입력할게."
- [확인] 1~2분 뒤 전면 `/` 새로고침.
- [주의] 시트의 날짜·장소 칸은 지금 전면에 쓰이지 않습니다(회차=코드).

**② 타임테이블·연사를 확정/수정한다**
- [상황] 연사 확정, 세션 시간·제목·요약 변경. (올해 회차 = 코드)
- [에이전트에게] "`editions/2026.ts` 의 `schedule` 에서 OO 세션의 연사를 'XX(소속 △△)'로, 제목/요약을 아래로 바꿔줘. 로컬에서 `/2026/` 타임테이블 확인하고 브랜치로 올려줘." 
- [확인] `/2026/` 타임테이블 해당 줄.
- [주의] `kind` 는 `공통`/`휴식`/트랙이름만. 시작 시각이 같은 줄은 한 행에 나란히 놓입니다.

**③ 발표자료(PDF)를 올리거나 교체·삭제한다**
- [상황] 연사가 공개 동의한 자료를 보내옴 / 교체 / 비공개로 내림.
- [에이전트에게] "연사 OOO(세션 slug: `indie-3`)의 발표자료를 올려줘. 파일은 `<경로>`에 있어. `public/slides/indie-3.pdf` 로 넣고 `editions/2026.ts` 의 `slides` 에 등록해. 로컬에서 그 세션에 '발표 자료 PDF' 버튼 뜨는지 확인 후 브랜치로."
  - 내릴 때: "`indie-3` 발표자료를 비공개로 내려줘. slides 에서 빼고 파일도 지워줘."
- [확인] `/2026/` 타임테이블 해당 세션 버튼 유무.
- [주의] **공개 동의한 연사만.** 비공개 연사(예: 하상석 `industry-1`)는 넣지 않습니다. 파일명은 세션 slug 와 일치시키기.

**④ FAQ 를 고친다** — [에이전트에게] "`editions/2026.ts` 의 `faq` 에 질문/답을 추가(또는 수정)해줘." / [확인] `/2026/` 하단 FAQ.

**⑤ 오시는 길·장소를 고친다** — [에이전트에게] "`editions/2026.ts` 의 `venue`(name/address/transit/mapUrl/note)를 아래로 바꿔줘." / [확인] `/2026/` 오시는 길.

**⑥ 동아리 로고를 추가하거나 홈페이지 링크를 단다**
- [에이전트에게] "`PartnersSection.tsx` 의 CLUBS 에 '△△대 □□'(로고 `public/images/logos/club-□□.png`, 홈페이지 `https://...`)를 추가해줘. 로고 없으면 자리만. 로컬 확인 후 브랜치로."
- [주의] 로고는 흰색·투명 PNG(3:1 캔버스). `url` 이 있으면 로고 아래 "홈페이지 ↗" 버튼이 생기고, 없으면 버튼 없음.

### 3-2. 회차 운영

**⑦ 내년 회차 페이지를 만든다**
- [상황] 2027 준비 시작.
- [에이전트에게] "2027 회차를 만들어줘. `editions/2026.ts` 를 복제해 `editions/2027.ts`(year 2027, no '제2회', 날짜·장소·타임테이블은 미정/임시, slides 비움). `editions/index.ts` 배열 맨 앞에 등록. `src/app/2027/page.tsx` 는 `2026/page.tsx` 복제 후 edition 만 교체. 전면 '지난 회차'에 2027 카드 뜨는지 로컬 확인하고 브랜치로."
- [확인] `/2027/` 열림 + 전면 카드.

**⑧ 다가오는 회차에 '참가 신청'을 연다 / 행사 뒤 아카이브로 전환한다**
- [상황] 현재 Hero 는 지난 회차용이라 "행사는 종료되었습니다"를 보여줍니다. **다가오는 회차**는 신청 버튼이 필요합니다.
- [에이전트에게] (신청 열기) "2027 은 다가오는 회차야. Hero 를 종료 안내 대신 **참가 신청 버튼**(신청 폼 링크)과 날짜·장소 안내가 보이게 맞춰줘. 신청 폼 주소는 `<링크>`. 회차 상태(status)로 분기하면 좋겠어. 로컬 확인 후 브랜치로."
- [에이전트에게] (행사 뒤) "2027 행사가 끝났어. status 를 past 로 바꾸고 Hero 를 발표자료·종료 안내로 돌려줘."
- [주의] 신청 폼 응답에는 개인정보가 쌓입니다 — 링크만 넣고, 응답 데이터는 사이트에 노출하지 않습니다.

### 3-3. 배포 · 장애

**⑨ 바꿨는데 라이브에 안 보인다**
- [대응] ① 캐시 새로고침(Ctrl/Cmd+Shift+R). ② 저장소 **Actions** 탭 초록불 확인. ③ **시트에서 고친 타임테이블/FAQ 라면 원래 안 바뀜**(회차는 코드·동결 — 가장 흔한 착각).
- [에이전트에게] "라이브 사이트(`curl` 공개주소)와 방금 변경이 맞는지 확인해줘."

**⑩ 배포가 실패했다(빨간 ✗)**
- [대응] Actions 에서 실패 항목 → `Build static site` 로그에 한글 이유. 시트 형식 문제면 시트 고치고 재실행.
- [에이전트에게] "방금 배포가 실패했어. 로컬에서 `npm run build` 돌려 같은 에러를 재현하고 원인을 고쳐줘. 고친 뒤 로컬 빌드가 통과하는지 확인하고 브랜치로."

**⑪ 화면이 스타일 없이 깨진다**
- [원인] 저장소 이름을 바꾸면 basePath(`/저장소이름/_next/...`)가 어긋납니다.
- [대응] 이름을 되돌리거나, 바꿨다면 **Actions 재실행**(재빌드 필수). [에이전트에게] "저장소 이름이 바뀐 것 같아. basePath/배포 설정 확인하고 재배포를 트리거해줘."

**⑫ 시트가 안 읽힌다 / 토큰이 만료됐다**
- [대응] 시트 공유가 "링크가 있는 모든 사용자·뷰어"인지(6-2), Apps Script 토큰 만료 여부(6-3) 확인. 토큰 만료 시 버튼만 안 되고 Actions 수동 실행은 됩니다.

## 4. 레퍼런스 — 파일 구조

```
src/
├─ app/
│  ├─ page.tsx            전면(범용 소개): Landing · About · Editions · Partners
│  └─ 2026/page.tsx       2026 아카이브: Hero · Program · Venue · FAQ …
├─ components/            섹션·공용 UI (PartnersSection 에 동아리 로고/링크)
├─ data/
│  ├─ content.json        시트에서 생성(상시 정보 원본)
│  ├─ conference.ts       상시 정보(시트 구독)
│  ├─ editions/2026.ts    2026 회차 데이터(동결)
│  ├─ editions/index.ts   회차 목록·헬퍼(latestEdition/getEdition)
│  ├─ editions/types.ts   Edition 타입
│  └─ schedule.ts         회차 공통 타입·헬퍼
└─ lib/asset.ts           public/ 경로에 배포 경로를 붙임
public/slides/            발표자료 PDF (<세션slug>.pdf)
public/images/logos/      동아리·후원 로고
```

개발 명령:

| 명령 | 하는 일 |
| --- | --- |
| `npm install` | 의존성 설치(처음 1회) |
| `npm run dev` | 개발 서버 http://localhost:3000 |
| `npm run build` | 정적 사이트를 `out/` 에 생성 |
| `npm run sheet:check` | 시트가 배포 가능한지 점검(`SHEET_ID` 필요) |

> 로컬 함정: dev 서버가 돌면 `next build` 가 `out` 잠김(EBUSY) → 빌드 전 dev 중지. 리팩터 후 dev 가 옛 화면이면 `.next` 삭제 후 재기동.

## 6. 레퍼런스 — 처음 한 번만 하는 설정

### 6-1. GitHub Pages
저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로.

### 6-2. 시트 연결
1. `sheet-template` 폴더 CSV 를 **파일 이름과 똑같은 탭**으로 구글 시트에 가져옵니다.
2. 시트 **공유 → "링크가 있는 모든 사용자 · 뷰어"**.
3. 시트 주소의 ID 복사: `.../spreadsheets/d/`**`이 부분`**`/edit`.
4. 저장소 **Settings → Secrets and variables → Actions → Variables → New variable**: Name `SHEET_ID`, Value 에 ID.

### 6-3. 시트 업데이트 버튼(Apps Script, 선택)
시트 **확장 프로그램 → Apps Script** 에 붙여 저장. **토큰은 코드가 아니라** 프로젝트 설정 → 스크립트 속성 `GITHUB_TOKEN`(Fine-grained PAT, `Contents: Read and write` + `Actions: Read`)에 넣습니다.

```javascript
const OWNER = 'Game-Dev-Conference-GAMEOVER';
const REPO  = 'GAMEOVER_Homepage';

function onOpen() {
  SpreadsheetApp.getUi().createMenu('GAME OVER?')
    .addItem('사이트 업데이트', 'updateSite')
    .addItem('배포 상태 확인', 'checkDeploy')
    .addToUi();
}
function token_() {
  const t = PropertiesService.getScriptProperties().getProperty('GITHUB_TOKEN');
  if (!t) throw new Error('스크립트 속성에 GITHUB_TOKEN 이 없습니다.');
  return t.trim();
}
function api_(path, options) {
  const opts = options || {};
  opts.headers = { Authorization: 'Bearer ' + token_(), Accept: 'application/vnd.github+json' };
  opts.muteHttpExceptions = true;
  return UrlFetchApp.fetch('https://api.github.com/repos/' + OWNER + '/' + REPO + path, opts);
}
function updateSite() {
  const ui = SpreadsheetApp.getUi();
  const res = api_('/dispatches', {
    method: 'post', contentType: 'application/json',
    payload: JSON.stringify({ event_type: 'update-content' }),
  });
  const code = res.getResponseCode();
  if (code === 204) { ui.alert('업데이트를 시작했습니다. 1~2분 뒤 「배포 상태 확인」을 눌러 보세요.'); return; }
  const hint = { 401:'토큰 확인', 403:'토큰 권한(Contents: Read and write) 확인', 404:'OWNER/REPO 철자 확인' }[code] || '알 수 없는 오류';
  ui.alert('실패 (' + code + ')\n' + hint);
}
function checkDeploy() {
  const ui = SpreadsheetApp.getUi();
  const res = api_('/actions/runs?per_page=1');
  if (res.getResponseCode() !== 200) { ui.alert('상태를 읽지 못했습니다 (' + res.getResponseCode() + ').'); return; }
  const run = JSON.parse(res.getContentText()).workflow_runs[0];
  if (!run) { ui.alert('실행 기록이 없습니다.'); return; }
  let msg = run.status !== 'completed' ? '빌드 중입니다. 조금 뒤 다시 눌러 보세요.'
          : run.conclusion === 'success' ? '성공했습니다. 홈페이지에 반영됐습니다.'
          : '실패했습니다. 아래 주소에서 이유를 확인하세요.';
  ui.alert(msg + '\n\n' + run.html_url);
}
```

> 토큰은 만료됩니다. 만료일을 인수인계 문서에 남기세요.

## 7. 문제 해결 요약

| 증상 | 원인과 해결 |
| --- | --- |
| 시트 고쳤는데 타임테이블 그대로 | **정상.** 회차는 코드로 동결(3-3 ⑨) |
| 바꿨는데 라이브에 없음 | 캐시 새로고침 + Actions 초록불 확인 |
| 빌드 실패(빨간 ✗) | Actions 로그 한글 이유 / 에이전트에 `npm run build` 재현·수정 요청(3-3 ⑩) |
| 저장소명 바꾼 뒤 화면 깨짐 | basePath — Actions 재실행 필수(3-3 ⑪) |
| 발표자료 버튼 안 보임 | `public/slides/` 파일 + `editions.slides` 등록 확인 |
| 시트 권한/탭 오류 | 공유 설정(6-2)·탭 이름 복구 |
| 버튼 401/403 | Apps Script 토큰 만료·권한(6-3) |
| 에이전트가 옛 화면/콘솔 에러 | `.next` 삭제 후 재기동 / 진짜 확인은 `curl localhost:3000` |
